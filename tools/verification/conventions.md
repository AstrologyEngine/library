# Replay chart regression fixtures

These fixtures contain outputs generated by a previous version of the astrology
engine. They are retained to detect behavioral regressions; they do not establish
independent astronomical accuracy. Tests consume the committed data without
requiring the historical implementation or a capture environment.

Do not regenerate expected values from changed code merely to make tests pass.
The metadata retains dataset identity, source hashes, and runtime versions.
The retained capture includes 456 charts, 308
boundary cases, 18 projection cases and both JavaScript Date limits. UTC and ET inputs retain their original
representations: converting all UTC inputs through floating-point ET seconds
loses instant precision and can change finite-difference speeds.

The captured dataset has SHA-256
`37773a57791bbadcb04ffe61348a8293f15e12831a7f69b7302170edbb2fe36e`,
12,712,840 bytes, and exact ET domain
`[-4733553600, 4732603200]` seconds. It is caller-supplied and is not committed.
Both full-chart runners verify its hash before evaluating it.

```sh
cargo test --locked --test conventions
CONVENTIONS_DATASET=/path/to/cheb.bin cargo test --locked --test conventions -- --include-ignored --nocapture
cd examples/configurable-chart
bun install --frozen-lockfile
bun run build:wasm
bun run verify /path/to/cheb.bin ../../target/conventions-wasm-report.json
```

The first command executes dataset-free boundary/projection checks and
unified chart structural checks. The full-chart native check is explicitly
ignored until the dataset is supplied. The Wasm runner executes the public
example adapter and its JSON configuration contract. In each full-chart run,
440 valid charts are compared and 16 overlapping polar house sets are rejected
under the engine's existing safeguards. Recorded speeds remain unchanged in the
True Sky projection; the existing Fagan–Bradley model is checked through the unified API
separately.

The tropical/search regression harness remains a separate check:

```sh
python3 tools/verification/parity.py --dataset /path/to/cheb.bin --report target/conventions-frozen-parity.json
```

The frozen tropical/search runner preserves the original captures and hashes.
Its migration policy independently identifies 247 overlapping house sets from
the frozen cusps and requires the explicit overlap error for exactly those rows.
The 1 overlapping HTTP adapter cases likewise require HTTP 500 with `internal`.
All other rows, including Whole Sign HTTP cusp omission and precise Sun-search
results, still compare exactly. Run `python3 tools/verification/test_chart_migration.py`
for negative controls covering unexpected errors, missing/extra rows, and changed
migration counts.

## Lahiri regression fixture

`tests/fixtures/lahiri-regression.json` pins the public `lahiri_ayanamsa` output at 1,593 UTC
inputs across 1800–2200 (a 97-day grid, a dense 2026 run for short-period nutation, fixed
reference instants, and both range edges, including one must-error input beyond each end).
`tests/lahiri_regression.rs` compares within 1 µas and also validates the fixture itself:
format, policy text, a minimum case count, unique inputs, finite values and the must-error cases.

Like the fixtures above, it detects regressions and does not establish accuracy. Its values come
from the library; accuracy rests on the external benchmark recorded under `validation` (the IAE
2027 mean formula plus NOVAS C 3.1 IAU 2000B nutation; see
`docs/plans/2026-11-12-lahiri-full-nutation.md`). Do not regenerate it merely to make a test pass.
If Lahiri output changes intentionally, explain the change, re-run the benchmark with `--final`,
then regenerate:

```sh
cargo run --locked --example lahiri_regression_fixture -- \
    --validated-by /path/to/lahiri-report-final.json \
    --output tests/fixtures/lahiri-regression.json
```

The generator refuses unless the report is a passing `--final` run whose validated `src/` tree is
identical to the current one, and it asserts that the out-of-range inputs still error. Regeneration
from unchanged code is byte-identical.

The imported fixture references the returned environment's Git revision and
external report. Those artifacts are not present in this repository, so its
regeneration requires recovering that history/report or performing a new,
explicitly documented benchmark validation. Keep the imported fixture unchanged
until then. Byte identity also requires the same recorded source revision.
